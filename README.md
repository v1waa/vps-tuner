# VPS Tuner

**Настольное приложение для управления Linux VPS по SSH.**

## Возможности

| Раздел | Что работает в 0.1.0 |
|---|---|
| Подключения | Несколько сохранённых профилей, пароль или приватный SSH-ключ, ключи с passphrase, проверка SSH fingerprint |
| Обзор | ОС, архитектура, CPU load, RAM, диск, время работы; обновление вручную или каждые 30 секунд |
| Аудит | Порты TCP/UDP и процессы, systemd-службы, Docker, Compose и каталоги приложений, SSH/firewall/TUN |
| Службы | Запуск, остановка, перезапуск, автозапуск, последние 200 строк журнала |
| Проекты | Обнаружение Compose, Node.js, Python, .NET, Go и Rust; Compose up/stop/pull/logs |
| Контейнеры | Состояние, образ, опубликованные порты, start/stop/restart/logs |
| Защита | Анализ SSH и внешних привязок, новый администратор с ключом, Fail2ban, UFW с автоматическим отключением при неподтверждённом доступе |
| Базы | PostgreSQL 17, MariaDB 11.4, Redis 7.4; случайные пароли, постоянные Docker volumes, привязка к localhost |
| Сайты | Nginx со своим HTML; Caddy reverse proxy с автоматическим HTTPS |
| Боты / приложения | Готовый Docker image или сборка Dockerfile из публичного Git-репозитория по полному SHA; переменные окружения |
| VPN | AmneziaWG userspace, Xray/VLESS+REALITY, WDTT/VK TURN; создание и отзыв AWG/Xray-клиентов |
| Туннели | Локальный TCP forwarding через SSH к панелям и БД; привязка только к 127.0.0.1 |
| Резервные копии | tar.gz файлов проекта, SQL dump PostgreSQL/MariaDB, скачивание файлов через SFTP |
| Операции | Предпросмотр команд, подтверждение критических действий именем хоста, живой вывод, сохранение результатов |
| Консоль | Собственный неинтерактивный Bash-сценарий с просмотром команд перед запуском |

Приложение управляет **удалённым Linux-сервером**, даже если запущено на Windows. Desktop x64. Автоустановка пакетов рассчитана на Debian/Ubuntu; универсальный аудит и управление существующими службами/контейнерами доступны на других Linux с необходимыми инструментами.

## Установка приложения

Откройте [Releases](https://github.com/v1waa/vps-tuner/releases).

- **Windows 10/11 x64:** `…-windows-x64-setup.exe` — установщик, `…-portable.exe` — переносимая версия.
- **Linux x64:** `.AppImage`, `.deb` или `.tar.gz`.
- Для AppImage: `chmod +x VPS-Tuner-*.AppImage`, затем запустите файл. Нужна поддержка FUSE; на Arch пакет `fuse2`. Можно также использовать архив `.tar.gz`.
- Для Debian/Ubuntu: `sudo apt install ./VPS-Tuner-*.deb`.
- Контрольные суммы файлов находятся в `SHA256SUMS.txt`.

Сборки первой версии не имеют платной подписи Windows. Не отключайте sandbox приложения; на Linux с ограниченными user namespaces используйте пакет `.deb` с его штатной настройкой sandbox.

## Начало работы

1. Нажмите **«Подключить VPS»**. Введите адрес, фактический внешний SSH-порт и пользователя.
2. Выберите пароль либо файл приватного SSH-ключа. Если ключ зашифрован, введите passphrase.
3. Сверьте показанный **SHA256-отпечаток** с консолью провайдера. После доверия приложение запомнит ключ. Неожиданная смена ключа блокирует подключение.
4. Приложение автоматически выполнит аудит. Профиль сохраняется, пароль и passphrase — нет.
5. При входе не под root для изменений нужен `sudo -n`. Отметьте его в профиле, если у пользователя уже настроено sudo без пароля. Без него доступен ограниченный аудит.
6. Откройте нужный раздел. Перед изменением проверьте план и целевой сервер. Для критических действий введите имя хоста.

Для аудита нужны `bash`, `coreutils` (`timeout`, `base64`), `iproute2`; отдельные проверки используют `systemd`, `sshd`, `nft`, `iptables`, `ufw`, `docker`. Отсутствующие инструменты отмечаются как недоступные проверки. Содержимое `.env`, ключей, конфигов приложений и `panel.db` при аудите не читается. Поиск файлов ограничен `/opt`, `/srv`, `/var/www`, `/home`, глубиной 4 и 150 результатами; это обнаружение типовых проектов, не полный анализ диска.

**Демо** показывает фиктивный сервер без подключения и не выполняет операций.

## VPN

### AmneziaWG

1. Установите Docker в разделе «Система», если его ещё нет.
2. В «VPN и туннели» установите AmneziaWG, выбрав свободный UDP-порт.
3. На VPS собираются официальные `amneziawg-go` и `amneziawg-tools` по фиксированным commit SHA. Поддерживается userspace-реализация, модуль ядра не устанавливается.
4. Используется отдельный контейнер с TUN/NET_ADMIN и сеть `10.77.0.0/24`. Нужны Python 3 (раздел «Базовые инструменты»), доступ к `/dev/net/tun` и внешнему UDP-порту.
5. Добавьте каждого клиента отдельно, с уникальным именем и номером IP 2–254.
6. Конфиг: `/opt/vps-tuner/awg/clients/ИМЯ.conf`. Укажите путь в «Данных доступа» и скачайте файл. Для просмотра через sudo есть кнопка «Показать».
7. Импортируйте конфиг в совместимый клиент AmneziaWG. Для отзыва используйте отдельный сценарий.

IPv4 получает выход в интернет. `::/0` в клиентском конфиге направляет IPv6 в туннель; серверный IPv6 egress этой версией не настраивается. Формат использует совместимые параметры AWG (Jc/Jmin/Jmax/S1/S2/H1–H4), без обещания маскировки под определённый сервис.

### Xray

- Проверяются SHA-256 готовых бинарников `v26.3.27` для amd64/arm64.
- Создаётся **отдельная** служба `vpst-xray.service` от пользователя `vpst-xray` и конфигурация `/etc/vps-tuner/xray/config.json`.
- Первый клиент: `/opt/vps-tuner/xray/clients/first.txt`. Дополнительные пользователи и отзыв — в каталоге.
- Настройте SNI доступного с VPS TLS 1.3-сайта, разрешите выбранный TCP-порт в firewall VPS/провайдера.
- При добавлении/отзыве клиента Xray перезапускается; текущие подключения кратковременно прерываются.
- Существующие Xray/3x-ui установки не импортируются в собственный конфиг. Их службы/контейнеры можно обслуживать отдельно.

### WDTT / VK TURN

- Устанавливается проверенный по SHA-256 upstream-бинарник `ildarmaga/wdtt v1.5.74`, собственная systemd-служба, локальная панель.
- Панель: `127.0.0.1:2860/wdtt/`. Логин `admin`; пароль задайте в форме. До первого запуска записывается bcrypt-хеш и loopback-привязка. Подписки из интернета отключены.
- Создайте SSH-туннель на порт **2860** и нажмите «Открыть». Там создавайте отдельных пользователей, лимиты и клиентские ссылки.
- Проверяются порты UDP **56000, 56001, 56003, 46000**, TCP **2860, 2861**. Служба и upstream добавляют свои NAT/forward/input-правила и включают IPv4 forwarding.
- Для транспорта VK TURN нужен совместимый клиент и действующий VK call hash. Приложение не получает VK-аккаунты и не генерирует хеши звонков.
- Подсети upstream: `10.66.66.0/24`, `10.70.0.0/16`. Перед установкой убедитесь, что они не пересекаются с вашей сетью.

Работа при конкретном белом списке не гарантируется: она зависит от сети оператора, доступности медиарелеев, клиента и актуальности upstream. **OpenFlux** обозначен экспериментальным; отдельного встроенного автоустановщика в 0.1.0 нет. Проверенный проект можно развернуть через Docker/Git или собственный сценарий.

## Firewall и существующие проекты

- Приложение не перезаписывает уже существующие каталоги и конфиги установок.
- Перед публикацией нового порта сценарий проверяет его через `ss`. Docker дополнительно проверяет конфликты при запуске.
- Сканирование адресов прослушивания не доказывает доступность из интернета. Firewall провайдера не виден через SSH.
- Включение UFW сохраняет **внутренний SSH-порт из текущего соединения** (в том числе при перенаправлении внешнего порта), а также перечисленные вами порты проектов.
- **Переподключитесь и подтвердите firewall за 120 секунд.** До подтверждения работает systemd timer, который отключит UFW. Подтверждение в исходной SSH-сессии запрещено.
- Автооткат отключает UFW, но не восстанавливает все настройки; копия `/etc/ufw` сохраняется в `/var/lib/vps-tuner/`. Уже активный UFW этим мастером повторно не включается.
- Публикация Docker-портов может обходить UFW. БД и обычные приложения по умолчанию публикуются на localhost. Сайт, VPN и HTTPS-прокси используют внешние порты.
- Автоматического отключения SSH-паролей, изменения SSH-порта и перезагрузки нет. Это делается вручную после проверки доступа по ключу.

## Данные и резервные копии

Профили, SSH fingerprints и метаданные операций: `config/state.json` в стандартном `userData` Electron (`%APPDATA%/vps-tuner` на Windows, `~/.config/vps-tuner` на Linux). Пароли SSH, passphrase, скрипты и вывод операций туда не записываются. Вывод доступен в памяти текущего окна; при необходимости сохраните его вручную. Логи сторонних служб могут содержать секреты.

Секреты БД создаются на сервере; Compose-файлы и каталоги проектов защищены правами. SFTP-скачивание выполняется с правами вошедшего SSH-пользователя, **не sudo**; для root-only архивов подключитесь под root или сохраните текстовый вывод через «Показать». Ограничение скачивания — 2 ГБ.

Архивы в `/var/backups/vps-tuner/` остаются на том же VPS до скачивания. Файловый архив не является согласованной копией живой БД и не включает отдельные Docker volumes; для SQL используйте «Резервная копия БД». Автоматическое расписание и мастер восстановления в первую версию не входят.

Если соединение оборвалось, итог удалённой команды может быть неизвестен. Приложение показывает **«Состояние неизвестно»**, а не успех. Перед повтором проверьте сервер. Установки не являются полностью транзакционными: при ошибке могут остаться пакеты или созданный каталог; приложение не удаляет их автоматически.

## Разработка

Нужен Node.js 22+ и npm.

```bash
npm ci
npm run dev
npm test
npm run build
npm run dist
```

`npm run dev` запускает Vite и Electron. Обычное приложение загружает только локальный `app://` интерфейс. SSH работает в main process; renderer изолирован, sandbox включён, Node API недоступен. IPC проверяет отправителя и входные данные. План одноразовый, привязан к SSH-сессии и действует 5 минут.

## Проверки

- Unit/security: shell injection, входные параметры, парсинг аудита, секреты, UFW reconnect, синтаксис каждого Bash-сценария.
- SSH integration: локальный тестовый SSH-сервер, host-key verification до пароля, статусы команд, обрыв канала, TCP forwarding.
- Desktop smoke: запуск Electron, все 12 разделов, отсутствие Node в renderer, подключение к тестовому SSH, аудит, подтверждение и выполнение команды, отключение.
- Disposable Ubuntu runner: реальные PostgreSQL/MariaDB/Redis и сайт в Docker, SQL dump, Xray, WDTT, сборка AmneziaWG, создание и отзыв клиентов.
- GitHub Actions собирает Windows x64 и Linux x64. Тег `v0.1.0` (или коммит файла `release-request.json` в main) публикует бинарники и SHA256SUMS после серверных/desktop-проверок и обеих сборок.

CI подтверждает запуск компонентов на тестовом Ubuntu VPS. Проходимость VK TURN и реальное подключение VPN-клиентов из сети с белым списком требует отдельной проверки в вашей сети.
